Xilinx各系列时序与延迟

Xilinx各系列时序与延迟

注：下列数值为“典型/工程估计范围”，用于快速预算与对比。精确分析请参照目标器件的 Data Sheet（DS）与相关 User Guide（UG），并以 Vivado 生成的 Timing Report 为准。(docs.amd.com)

一、触发器（CLB FF）建立时间（Tsu）与保持时间（Th）

  • 说明：Tsu/Th 与器件家族、速度等级、温度/电压及触发器类型（带/不带异步复位）有关；Data Sheet 给出器件、速度等级下的具体值（常给出典型 / 最大 / 最小值）。请用器件 DS 中的 “AC Switching Characteristics” 表格做最终验证。(docs.amd.com)
系列 典型 Tsu（估计） 典型 Th（估计） 说明 / 参考
7 Series（Artix/Kintex/Virtex） ~0.3 – 0.8 ns ~0.1 – 0.5 ns 依速度等级（-1/-2 等）与器件不同而变动；参考 DS180 中的 AC switching 表格。(docs.amd.com)
Spartan-7 ~0.4 – 0.9 ns ~0.2 – 0.6 ns 入门级，速度等级较低，见 Spartan-7 DS（DS189）。(docs.amd.com)
UltraScale / UltraScale+ ~0.25 – 0.6 ns ~0.1 – 0.4 ns 工艺与布局改进通常令部分时序优化；参考 UltraScale/UltraScale+ DS 与相关 UG。(docs.amd.com)
Versal (ACAP) ~0.2 – 0.5 ns ~0.1 – 0.3 ns Versal 的同步结构和 NoC/时钟资源不同，Tsu/Th 仍需查看 DS950/相关文档。(穆尔森)

提示：不要把单一数值当成“通用真值” —— 比如同一系列不同 speed-grade（-1、-2）与温度/电压条件会显著改变 Tsu/Th（Data Sheet 会列出 speed-grade 相关的具体项）。(docs.amd.com)

二、组合逻辑延迟（LUT / 逻辑级数 / 进位链 / DSP）

1) 单级 LUT 延迟（典型）

  • 典型量级：~150–450 ps（0.15–0.45 ns）/LUT 级，具体随器件与实现（LUT6、是否有映射到专用级联路径）而变。
    解释：Data Sheet 中 CLB 的时序（Clock-to-Q / Tco、logic path delays）与 Vivado 报告可反推单级 LUT/CLB 的近似延迟。对于高性能器件或更快 speed-grade，该值偏低；低速器件或复杂布线下偏高。(docs.amd.com)

2) 多级逻辑（级联）与进位链

  • 多级 LUT 级联（3 级）：估计 ~0.5–1.2 ns（包含布线开销）。
  • 进位链 (CARRY4/CARRY8 等)：每 bit 的 effective carry 延迟 典型约 40–80 ps/bit（不同器件略有差异；CARRY4 实现 4 位段，实际最快加法可达几百 ps 的总体延迟，依 pipeline 与布线而定）。(ResearchGate)

3) DSP（专用乘/累加）延迟

  • 量级：对完整的乘-累（无 pipeline）路径，通常是 数 ns 级（例如 2–6 ns），具体视 DSP 版本（DSP48E1 / DSP48E2 / Versal 的 DSP）与是否启用 pipeline 寄存器而定。带 pipeline 的 DSP 能以更高频率工作（降低组合延迟但增加寄存器阶段）。请参考 DSP UG/DS 的 Switching Characteristics 表。(AMD)

三、布线（互连）延迟

  • 趋势：布线延迟与物理距离与所选路由资源密切相关。一般结论：

    • 同 Slice / 同 CLB 内：几十至数百皮秒（~50–200 ps）；
    • 跨 CLB / 模块级：几百 ps 到几 ns（~0.3–2 ns），视距离与拥塞情况而定；
    • 长跨芯片/远距：可达到数 ns（若跨整个芯片/package 路由，延迟可达几 ns 到 10+ ns 的极端情况，取决于器件大小与互连层使用）。

  • Xilinx Data Sheet/Architecture 文档强调：互连延迟通常是时序的主导项，需要靠布局（LOC/RLOC）和管脚/约束来优化。Vivado 的 Timing Report 与后布局时序估计（post-route）是最终依据。(docs.amd.com)

四、I/O、IODELAY 与 时钟网络（Clocking）

  • IODELAY（IDELAY/ODELAY）tap 延迟：不同家族的 tap 值与实现不同，Data Sheet 中给出典型 tap 时间与最大范围（例如 Spartan/7 与 7-series、UltraScale+ 的实现和单位差别较大），应以目标器件的 I/O 文档为准（IDELAYTAPS、TAP_DELAY 等参数在 DS/UG 中列出）。(docs.amd.com)
  • 全局时钟 BUFG / 时钟网络延迟：全局时钟缓冲相比普通布线的延迟要小、且更可预测（clock tree 的 skew 与延迟由时钟资源类型决定）。Versal/UltraScale+ 的时钟网络与传统 7-series 有架构差异（如 NoC 与专有时钟分布），请参阅 Clocking Architecture 文档。(0x04)

五、工程实践建议（来自官方建议与行业实践）

  1. 以器件 Data Sheet（DS）为准：所有精确的 Tsu/Th、Tco、Tpd、IODELAY tap 等参数都写在器件的 DS 或对应 UG 的 Switching Characteristics 表格里。Vivado 的 Timing Report（合成后、布局后）给出针对当前实现的精确数值。(docs.amd.com)
  2. 使用后布局（post-route）Timing Report 校核真实延迟：预估有用，但后布局报告才是可用于签核的数值。
  3. 对关键路径做布局约束（LOC/RLOC/Pblock）并使用区域约束减少布线延迟。
  4. 利用流水线与专用资源（carry chain、DSP、BRAM）减小组合深度。
  5. 对高速 IO/SerDes 使用器件提供的 PHY/IP 与 IO timing guide（包括 IDELAY/IODELAY 的校准）。(AMD)
