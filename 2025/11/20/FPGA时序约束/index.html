FPGA时序约束

1. FPGA时序约束的主要类别

类别 常用命令 应用场景
时钟约束 create_clock, create_generated_clock, set_clock_groups 定义所有时钟特性
IO 约束 set_input_delay, set_output_delay, set_load 与外设接口的时序匹配
时序例外 set_false_path, set_multicycle_path, set_max_delay 异步、复位、多周期路径
物理约束（辅助时序） LOC, Pblock, SLICE/BEL 布局影响时序，非 STA 约束
不确定性/延迟类 set_clock_uncertainty, set_clock_latency 建模抖动、偏斜

2. 时序约束的基本概念

2.1 时钟偏差（Clock Skew）

2.1.1 时钟偏差的定义

Clock Skew = 同一个时钟在不同触发器处到达时间的差异

在晶振 → PLL → 全局时钟树 的传输过程中，每条时钟分支的电气路径、负载、布线长度都不一样，所以：

  • CLK 到达触发器 FF1 的时间为 ( tclk1t_{clk1}tclk1​ )
  • CLK 到达触发器 FF2 的时间为 ( tclk2t_{clk2}tclk2​ )
Skew=(tclk2−tclk1) Skew = ( t_{clk2} - t_{clk1} ) Skew=(tclk2​−tclk1​)

这就是时钟偏差（正负均可能）。

2.1.2 Skew 的两种类型

类型 定义 对 Setup 的影响 对 Hold 的影响 说明
正 Skew 目的寄存器时钟到达较晚 (tclk2>tclk1t_{clk2} > t_{clk1}tclk2​>tclk1​) 有利于 Setup（建立时间） 不利于 Hold（保持时间） 采样时间被延后
负 Skew 目的寄存器时钟到达较早 (tclk2<tclk1t_{clk2} < t_{clk1}tclk2​<tclk1​) 不利于 Setup 有利于 Hold 采样时间被提前

2.1.3 Skew 对时序的影响

基本概念

1. 建立时间（Setup Time）

数据 在时钟上升沿到达前 必须保持稳定的最短时间。

2. 保持时间（Hold Time）

数据 在时钟上升沿之后 必须继续保持稳定的最短时间。

3. 建立时间裕量（Setup Slack）

在实际路径延迟下，是否还有多余的时间满足 setup 要求（越大越安全，负值表示违反）。

4. 保持时间裕量（Hold Slack）

在实际路径延迟下，是否还能满足 hold 要求（越大越安全，负值表示违反）。

四者的本质区别

名称 是什么？ 决定于？ 反映什么？
建立时间 触发器本身的硬件要求 由工艺/器件决定，固定值 数据必须提前多长时间稳定
保持时间 触发器本身的硬件要求 由工艺/器件决定，固定值 数据必须延后多长时间稳定
建立时间裕量（Setup Slack） “数据是否赶得上下一拍” 数据路径延迟 、时钟周期 、skew 是否存在 setup violation
保持时间裕量（Hold Slack） “数据是否太快改变” 数据最小延迟 、 skew 是否存在 hold violation
时钟偏差对建立/保持时间裕量的影响

1. 对建立时间裕量 (Setup Slack) 的影响

建立时间检查是为了确保数据在时钟沿到来之前已经稳定。

  • 公式:

    Setup Slack=(Tclk+Tskew)−(Tcq+Tcomb+Tsetup) Setup\ Slack = (T_{clk} + T_{skew}) - (T_{cq} + T_{comb} + T_{setup}) Setup Slack=(Tclk​+Tskew​)−(Tcq​+Tcomb​+Tsetup​)

    (其中 TclkT_{clk}Tclk​ 为时钟周期， TcqT_{cq}Tcq​ 为触发器输出延时，TcombT_{comb}Tcomb​ 为组合逻辑延时)

  • 分析:

    • 正偏差 (Tskew>0T_{skew} > 0Tskew​>0): 捕获时钟到得晚。这就像是“终点线后移了”，数据有更多的时间从起点（发射）跑到终点（捕获）。
      • 结论: 增加建立时间裕量（对 Setup 有利）。
    • 负偏差 (Tskew<0T_{skew} < 0Tskew​<0): 捕获时钟到得早。这就像是“终点线前移了”，数据必须跑得更快才能赶上。
      • 结论: 减少建立时间裕量（对 Setup 不利）。

2. 对保持时间裕量 (Hold Slack) 的影响

保持时间检查是为了确保在时钟沿到来之后，数据能保持稳定一段时间，不被新数据冲掉。

  • 公式:

    Hold Slack=(Tcq+Tcomb)−(Thold+Tskew) Hold\ Slack = (T_{cq} + T_{comb}) - (T_{hold} + T_{skew}) Hold Slack=(Tcq​+Tcomb​)−(Thold​+Tskew​)

    注意：这里 TskewT_{skew}Tskew​ 是减项（或者说是移到了不等式的另一边）。

  • 分析:

    • 正偏差 (Tskew>0T_{skew} > 0Tskew​>0): 捕获时钟到得晚。这意味着捕获触发器要等待更久才采祥。如果在等待期间，新数据跑得太快（TcombT_{comb}Tcomb​ 很短）赶上来了，就会破坏旧数据。
      • 结论: 减少保持时间裕量（对 Hold 不利，容易导致 Hold Violation）。
    • 负偏差 (Tskew<0T_{skew} < 0Tskew​<0): 捕获时钟到得早。捕获触发器在数据变化之前就早早地完成了采样。
      • 结论: 增加保持时间裕量（对 Hold 有利）。

3. 总结对照表

时钟偏差类型 定义 (Tcap−TlaunchT_{cap} - T_{launch}Tcap​−Tlaunch​) 对建立时间 (Setup) 的影响 对保持时间 (Hold) 的影响 物理直觉
正偏差 (Positive Skew) >0> 0>0 (捕获时钟晚到) 变好 (裕量增加) 变差 (裕量减少) 给了数据更多时间传输，但增加了新数据冲毁旧数据的风险。
负偏差 (Negative Skew) <0< 0<0 (捕获时钟早到) 变差 (裕量减少) 变好 (裕量增加) 压缩了数据传输时间，但数据一旦锁存，非常安全，不易被冲毁。

2.1.4 Skew 的来源

来源 解释
布线长度不同 某个寄存器离 BUFG/MUX/PLL 更远
负载差异 不同区域的 fanout 不一致
时钟树结构不对称 FPGA 时钟网络虽优化，但仍有差异
温度/电压 PVT 变化 不同区域芯片条件不一致
跨时钟区域 BUFGCE/BUFH 等本地时钟资源差异
