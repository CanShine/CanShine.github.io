2 AXI4-Full与其他AXI协议的区别

2.1 AXI 与 AHB 的对比

局限类别 AHB 问题描述 对系统影响 AXI 的改进与优化
通道结构 只有一条共享总线（地址/控制/数据共用） 无法并行传输，多主争用带宽下降 分为 5 条独立通道（AR、AW、W、R、B），支持并行
握手机制 固定 HREADY/HRESP 握手 流控粗糙、延迟大 Valid/Ready 握手灵活，可细粒度流控
读写操作 读写共用同一总线 无法同时读写，流水化差 读写完全分离，可并行传输
事务控制 Burst 事务粒度大，不能中断或乱序完成 灵活性低，事务阻塞 支持多事务交织与乱序完成（ID-based）
仲裁结构 仲裁集中且与译码耦合 扩展困难，多主系统复杂 支持分布式互联（Crossbar、NoC），模块化更好
时序耦合 地址、控制、数据时序绑定 难以提升频率、跨时钟域传输 通道独立握手，易于跨时钟域和高频实现
响应机制 仅有 OKAY、ERROR 两类响应 功能简单，难支持缓存一致性或 QoS 提供多种响应（OKAY、EXOKAY、SLVERR、DECERR），并支持 QoS
系统扩展 不支持缓存、保护等属性 难满足高性能多核需求 支持 QoS、Cache、Protection 等属性扩展

2.2 AXI4-Full 与 AXI4-Lite 的区别

对比维度 AXI4-Full AXI4-Lite
设计目的 高性能内存访问、数据搬运（CPU↔DDR、DMA、外设等） 简单寄存器访问（控制配置接口）
数据通道 5 条通道（AR、AW、W、R、B） 5 条通道（AR、AW、W、R、B）
突发传输 (Burst) ✅ 支持 INCR/WRAP/FIXED，最多 256 拍 ❌ 不支持突发，每次仅传一个数据
地址自动递增 ✅ 支持 ❌ 不支持
传输宽度 (Data Width) 灵活可配，8～1024 bit，常见 32/64/128/256 bit 固定且较小，通常 ≤ 32/64 bit
复杂度 较高，需处理突发、缓存、QoS 等信号 简单，信号少、控制逻辑轻量
系统用途 存储器接口、DMA、高速外设（如 GPU、加速器） 控制寄存器、配置寄存器访问
性能取向 高带宽、高吞吐量 低延迟、低开销
典型例子 AXI Master (CPU) ↔ AXI Slave (DDR/控制器/DMA) AXI Master (CPU) ↔ AXI Slave (外设控制)

2.3 AXI4-Full 与 AXI4-Stream 的区别

对比维度 AXI4-Full AXI4-Stream
设计目的 面向存储器读写（Memory-Mapped Interface） 面向高速数据流传输（Streaming Interface）
寻址方式 ✅ 有地址信号（ARADDR、AWADDR） ❌ 无地址信号，数据连续流动
数据方向 双向（支持读、写两种事务） 单向（Producer → Consumer）
通道数量 5 条通道：AW、W、B、AR、R 1 条主要通道：TVALID/TREADY/TDATA（可选 TKEEP、TLAST）
传输粒度 面向数据块或内存单元 面向数据流（包、帧、像素、样本等）
突发传输 ✅ 支持（burst，自动递增地址） 不需要突发机制（天然连续）
典型用途 CPU、DMA 与 DDR、外设之间的数据搬运 视频、音频、网络流、AI 加速器数据输入输出
传输控制 由主设备发起读写请求并完成应答 由数据源持续发送，接收端按 ready 控制
握手信号 Valid/Ready + 地址控制信号 仅 Valid/Ready（简化）
数据包结束标志 无特定标志（由突发长度控制） 有 TLAST 信号指示帧结束
性能特征 高可靠性、适合内存访问 高吞吐、低延迟、流水化强
系统场景 AXI Master (CPU/DMA) ↔ AXI Slave (DDR/外设) AXI-Stream Source ↔ AXI-Stream Sink（如视频流、FFT）

2.4 AXI4 与 AXI3 的区别

对比维度 AXI3 AXI4 变化说明
协议版本 AMBA 3.0 AMBA 4.0 AXI4 是 AXI3 的升级版
突发长度 (Burst Length) 最多 16 拍（4-bit LEN） 最多 256 拍（8-bit LEN） 长突发传输效率提升
写数据握手方式 需要 WID（Write ID） 移除 WID 信号 总线更简化，连线更少
读写乱序支持 支持多 ID 并可乱序完成 保留多 ID，写通道强制顺序完成 主从交互逻辑简化
窄传输支持 支持（可低于总线宽度） 保留支持 无本质变化
锁存传输 AxLOCK[1:0] 精简为单比特 AxLOCK 兼容 AXI-Lite 格式
写响应通道 (B) 支持多响应 ID 强制顺序写响应（与写地址顺序一致） Slave 逻辑简化
缓存/QoS 属性 AxCACHE、AxQOS、AxPROT 保留并增强 QoS 功能更丰富
支持通道数量 5 通道（AW/W/B/AR/R） 同样 5 通道 通道机制保持一致
互联结构 多主共享总线或 crossbar 更偏向 crossbar / NoC 适配更大规模 SoC
兼容性 不兼容 AXI4-Lite/Stream 完全兼容 AXI4-Lite/Stream 统一 AXI 生态
主要应用场景 早期 Cortex-A9/A8 SoC Cortex-A15、A53、Zynq、MPSoC 等现代平台 AXI4 已成为主流

3. AXI4-Full信号特性

3.1 乱序与交织的区别

概念 乱序 (Out-of-Order) 交织 (Interleaving)
定义 多个事务的完成顺序与发起顺序不同 多个事务的数据拍（beat）交叉传输
关注层次 事务级（Transaction level） 拍级（Beat level）
关键对象 不同事务之间的“完成顺序” 不同事务数据在总线上的“排列顺序”
典型现象 先发起的事务后完成 两个事务的数据交替出现在总线上
是否允许乱序完成 ✅ 支持（按 ID 区分） ✅ 可交织，但同一 ID 内仍保持顺序
AXI3 支持情况 ✅ 支持乱序和交织 ✅ 支持（同一通道可交叉传数据）
AXI4 支持情况 ✅ 保留乱序（按 ID） ❌ 移除交织，强制同一 ID 顺序完成
实现复杂度 中等 高（需交织缓存、标签追踪）
目的 提高并发性、利用 Slave 带宽 提升总线利用率、减少空闲周期

3.2 ID 信号的作用

情况 是否乱序 是否交织 是否必须 ID 原因
乱序 + 交织 ✅ ✅ ✅ 响应乱序且数据交错，必须 ID 匹配事务
乱序 + 非交织 ✅ ❌ ✅ 响应乱序，即使每个事务数据连续，也必须 ID 匹配事务
顺序 + 交织 ❌ ✅ 可选 响应顺序一致，规律可预测可用计数区分
顺序 + 非交织 ❌ ❌ ❌ 响应顺序一致，数据连续，用顺序和 RLAST/WLAST 就能区分

3.3 写操作与读操作的响应时机区别

特性 写操作（Write） 读操作（Read）
阶段 地址（AW）→ 数据（W）→ 写响应（B） 地址（AR）→ 数据（R）
突发传输 支持多个 beats 支持多个 beats
响应时机 整个突发完成后才产生一次写响应（BVALID + BRESP） 每一拍数据都返回响应（RRESP），最后一拍同时带 RLAST
响应作用 针对整个突发事务 针对每一拍数据，标识该拍数据状态
ID 信号 BRESP 携带 BID，标识对应写请求 每拍 RDATA 带 RID，标识所属读请求
结论 写操作完成后才响应一次 读操作每拍都响应，最后一拍标记突发结束

3.4 写操作与读操作的事务特性区别

操作类型 地址（A） 数据（D） 响应（R） 备注
写 W 先/同时/后 可流水化发送 整个突发完成后返回一次 BVALID + BRESP + BID
读 R 必须先发 从设备返回，每拍带响应 每拍数据都有 RRESP，最后一拍带 RLAST 数据可顺序或乱序返回，需 RID 匹配事务

3.5 事务标识 (Transaction ID)

组成部分 是否必需 说明
主机 ID ✅ 必须，区分不同主机发出的事务
事务编号 ✅ 区分同一主机发给同一从机的多事务

4. AXI 地址对齐与突发长度限制

4.1 地址对齐与每拍数据大小

  • 地址对齐

    • 定义：每次事务的起始地址必须是每拍数据大小的整数倍。
    • 公式：起始地址 2^SIZE == 0

  • 每拍数据大小（AWSIZE / ARSIZE）

    • 定义：信号 AWSIZE（写）/ ARSIZE（读）指定每拍（beat）的字节数。
    • 编码规则（SIZE = log₂(每拍字节数)）：| SIZE | 每拍字节数 |
      | ---- | ---------- |
      | 0 | 1 Byte |
      | 1 | 2 Bytes |
      | 2 | 4 Bytes |
      | 3 | 8 Bytes |
      | … | … |

  • 示例：

    • SIZE = 2 → 每拍 4 Bytes → 起始地址必须是 4 的倍数（0x0, 0x4, 0x8, …）
    • SIZE = 3 → 每拍 8 Bytes → 起始地址必须是 8 的倍数（0x0, 0x8, 0x10, …）

4.2 AXI 4K 边界总结

4.2.1 4K 边界定义与限制

  • 定义：地址能被 4 KB（0x1000）整除的位置，即地址低 12 位为 0。地址 0x1000 == 0

  • AXI 突发传输限制：

  • INCR（递增）突发：不能跨 4K 边界，超出需拆分事务

  • WRAP（循环）突发：循环地址必须在 4K 边界内

  • 核心原则：突发事务必须在 4K 页内完成，否则需要拆分。

  • 原因：

    1. 硬件和内存页设计简化
    2. DMA / 内存控制器通常以 4 KB 为页单位

4.2.2 4K 边界检查与突发拆分逻辑

代码解析与原理

实现逻辑

  • 计算本次突发长度：
    • 不跨 4K 且剩余长度 ≤ 255 → inc_rlen
    • 跨 4K → araddr_4k_gap
    • 剩余长度 > 255 → 255 beats
  • 计算结束地址 → 用于判断是否跨 4K 边界（XOR bit12）
  • 如果跨页 → 将突发拆分，第一个突发传输到 4K 边界
  • M_AXI_ARLEN：本次 AXI 突发长度
  • 逻辑说明：
    • 如果跨 4K 边界（araddr_4k_bdry = 1）→ 用 4K gap 拆分突发（araddr_4k_gap）
    • 否则 → 用剩余长度与最大突发长度比较（inc_rlen）
  • inc_rlen：不跨 4K 的情况下，本次突发长度
  • 逻辑说明：
    • 剩余长度 > 255 → 本次突发长度取 255
    • 剩余长度 ≤ 255 → 本次突发长度 = 剩余长度 - 1（ARLEN = N-1）
    • 剩余长度为 0 → 突发长度 0
  • end_raddr：本次突发的结束地址（不包括最后一拍的偏移）
  • araddr_4k_bdry：检查是否跨 4K 边界
    • XOR 地址的第 12 位（0x1000 对应 bit12）
    • 结果为 1 → 跨越 4K 边界；0 → 未跨越
  • araddr_4k_gap：突发跨 4K 时，计算第一个突发长度，保证不跨页
    • {M_AXI_ARADDR[31:12]+1, 10'h0}：下一个 4K 页的起始地址（低 12 位清零）
    • M_AXI_ARADDR[31:2]：当前地址（每 beat 4 Bytes，右移 2 位）
    • 差值即当前页内可传输的 beats 数量

5 AXI 与大小端（Endianness）总结

5.1 大小端定义

  • 小端模式（Little Endian）：低地址存放数据的最低有效字节（LSB）
  • 大端模式（Big Endian）：低地址存放数据的最高有效字节（MSB）
  • AXI 总线本身不限制大小端，遵循处理器和外设的模式即可

5.2 小端模式详解

  • 存储特点：低地址对应低字节，高地址对应高字节
  • 硬件设计习惯：多数 ARM 系统使用小端模式
  • 示例（32 位数据 0x01234567）：
    地址 存储内容
    0x0 0x67
    0x1 0x45
    0x2 0x23
    0x3 0x01

5.3 大端模式详解

  • 存储特点：低地址对应高字节，高地址对应低字节
  • 应用场景：通信类数据包传输
  • 示例（32 位数据 0x01234567）：
    地址 存储内容
    0x0 0x01
    0x1 0x23
    0x2 0x45
    0x3 0x67

5.4 ARM 处理器支持

  • 同时支持 小端（Little Endian） 和 大端（Big Endian） 模式
  • 无专门的 AXI 信号指示大小端，模式由处理器控制
  • 历史演变：
    • 早期 ARM 支持 BE-8 和 BE-32 两种大端模式
    • 现代处理器主要支持 BE-8

5.5 BE-8 与 BE-32 区别

  • BE-8：改变字节顺序，字节内部比特位保持不变
  • BE-32：保持字内部比特位不变，改变字顺序
  • 现代 ARM：主要支持 BE-8

*示例

访问类型 小端结果 大端结果
Word (0x0-0x3) 0x01234567 → 0x67452301 0x01234567 → 0x01234567
Halfword (0x0-0x1) 0x3210 0x0123
Byte (0x0) 0x0 0x0

6. AXI 突发类型与应用场景

6.1 突发类型概述

突发类型 (axi_arburst) 模式名称 地址变化方式 是否回绕 应用场景
2'b00 Fixed Burst 地址不变 否 访问固定寄存器
2'b01 Incremental Burst 每拍地址递增 1 个传输宽度 否 连续读写内存
2'b10 Wrapping Burst 每拍地址递增 1 个传输宽度，达边界时回绕到起点 是 Cache line 读写
  • 地址低位通常按数据宽度对齐（如 4 字节）

6.2 不同突发类型代码实现

6.2.1 固定突发（Fixed Burst，2’b00）

  • 所有拍的地址都不变，始终读取同一个地址（常用于访问固定寄存器）。

6.2.2 递增突发（Incremental Burst，2’b01）

  • 每拍地址递增一个数据宽度（如 4 字节），适合连续读写内存。
  • 地址低位对齐到数据宽度（如 4 字节对齐）。

6.2.3 回绕突发（Wrapping Burst，2’b10）

  • 地址达到回绕边界时，回到起始地址（适合 cache line 读写）。
  • 否则与递增突发类似，地址递增。

7. AXI 写使能信号（WSTRB）机制

7.1 WSTRB 信号定义

  • WSTRB（Write Strobe）：写字节使能信号
  • 位宽：C_S_AXI_DATA_WIDTH/8 位（每字节对应一位）
  • 功能：指示哪些字节有效，允许部分字节写入

7.2 WSTRB 代码示例

  • S_AXI_WSTRB 是 AXI4 的写字节使能信号，每一位对应一个字节（8 bit）。
  • C_S_AXI_DATA_WIDTH/8 表示总共有多少个字节（如数据宽度为 32 位，则有 4 个字节）。
  • for 循环遍历每个字节索引 byte_index。
  • if (S_AXI_WSTRB[byte_index] == 1)：如果该字节使能为 1，表示允许写入。
  • slv_reg1[(byte_index*8) +: 8] <= S_AXI_WDATA[(byte_index*8) +: 8];
    • 将写数据 S_AXI_WDATA 的对应字节写入寄存器 slv_reg1 的相应位置。

7.3 区别于 AXI4-Stream

  • AXI4-Full 的 WSTRB：每一位为 1 表示对应字节有效，数据会写入目标寄存器；为 0 表示该字节无效，不写入，但数据位仍然存在。
  • AXI4-Stream 的 TSTRB：每一位为 1 表示对应字节有效，数据会被接收；为 0 表示该字节无效，但数据位仍然占用带宽。
  • AXI4-Stream 的 TKEEP：每一位为 1 表示对应字节有效，数据会被接收；为 0 表示该字节无效，可以丢弃，不占用带宽。

区别总结：

  • TSTRB 为 0 时数据无效但仍传输；
  • TKEEP 为 0 时数据无效且可以丢弃；
  • WSTRB 为 0 时数据无效但数据位仍存在于总线。
