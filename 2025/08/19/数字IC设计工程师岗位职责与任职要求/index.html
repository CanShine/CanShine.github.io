数字IC设计工程师岗位职责与任职要求

数字IC设计工程师岗位职责与任职要求

🔹 数字 IC 前端设计完整流程

以Synopsys 工具链为例：架构分析 (Platform Architect) → RTL 编码 (VS Code) → 功能验证 (VCS+Verdi+VC Formal) → 静态检查 (SpyGlass Lint/CDC/RDC) → 逻辑综合 (DC/Fusion Compiler) → 等价性检查 (Formality) → 输出网表和约束交付后端。

1️⃣ 需求分析 & 架构设计

  • 工作内容
    • 阅读需求文档，理解系统指标（功能、时序、功耗、面积）
    • 设计模块划分、接口定义、时钟/复位架构
    • 产出 架构文档、接口文档
  • 工具
    • Synopsys Platform Architect （做系统级建模/性能分析，有时由系统工程师使用）
    • 日常多用 Word/Excel/Visio/Markdown

2️⃣ RTL 设计（RTL Coding）

  • 工作内容
    • 使用 Verilog/SystemVerilog 编写 RTL
    • 遵循可综合、时序友好的编码规范
    • 做 Code Review
  • 工具
    • VS Code：代码编辑器
    • VCS：语法检查
    • Verdi：仿真调试

3️⃣ 功能验证（Functional Verification）

（这部分可由验证工程师完成）

  • 工作内容
    • 搭建 UVM 验证环境
    • 编写 Testbench、激励、断言（SVA）
    • 做功能仿真，收集覆盖率（代码覆盖率 + 功能覆盖率）
    • 验证 RTL 是否满足设计需求
  • 工具
    • VCS ：Synopsys 主力 RTL 仿真器 ，支持 SystemVerilog / UVM / SVA ，用于功能验证和代码/功能覆盖率统计
    • Verdi ： 仿真波形调试与可视化工具 ，可用于 RTL 和门级波形浏览、覆盖率分析、信号追踪
    • VC Formal ： 形式验证工具 ，用于 断言验证（SVA） 、等价性检查以及形式化覆盖分析，辅助发现潜在逻辑问题

4️⃣ 静态检查（Static Check）

  • 工作内容
    • 检查 RTL 是否存在潜在问题
    • Lint ：语法、可综合性、风格
    • CDC/RDC ：跨时钟域/跨复位域分析，避免亚稳态和复位异常
  • 工具
    • SpyGlass Lint / CDC / RDC

5️⃣ 逻辑综合（Logic Synthesis）

  • 工作内容
    • 将 RTL 转换为门级网表
    • 加入约束文件（SDC：时钟定义、IO 延迟、功耗/面积目标）
    • 优化电路，满足时序、面积、功耗指标
  • 工具
    • Design Compiler (DC) ：业界最常用的逻辑综合工具
    • Fusion Compiler ：新一代工具，综合+物理优化一体化

6️⃣ 等价性检查（LEC）

  • 工作内容
    • 检查综合前 RTL 与综合后网表是否功能等价
    • 确保综合过程未引入逻辑错误
  • 工具
    • Formality ：Synopsys 等价性检查工具

7️⃣ 前端交付（Handoff to Back-End）

交付物 说明
功能验证通过的 RTL 代码 设计实现的核心，确保功能正确
时序/约束文件（SDC） 指导后端综合、布局布线的时序约束
Lint/CDC 报告 代码质量、跨时钟/复位域分析报告
门级网表（Gate-level Netlist） 供后端进行布局布线的门级电路描述
LEC 等价性检查报告 验证综合前后功能一致性
功能验证环境和覆盖率报告 便于后端或验证团队复现仿真环境，保证覆盖率

🔹 Synopsys 前端开发工具链总览

流程阶段 Synopsys 工具
架构建模 Platform Architect
RTL 编码 SpyGlass Lint
功能仿真 VCS + Verdi
形式验证 VC Formal
CDC/RDC 检查 SpyGlass CDC/RDC
逻辑综合 Design Compiler / Fusion Compiler
等价性检查 Formality

🔹 设计工程师所需提交材料

材料 提交对象 说明
RTL 代码 验证工程师 / 后端 功能实现核心
SDC 约束 后端 指导综合和时序分析
SVA 断言 验证工程师 形式验证和仿真验证
功能文档 / 接口说明 验证 / 后端 确保团队理解模块
SpyGlass 报告 验证 / 后端 确保代码质量
门级网表及综合报告 后端 辅助下游流程

交付流程建议：

  1. 交付前确保所有报告无严重问题，RTL 通过验证。
  2. 交付顺序建议：RTL → 约束 → 报告 → 网表 → 验证环境。
  3. 注意版本管理，确保交付物一致性。
