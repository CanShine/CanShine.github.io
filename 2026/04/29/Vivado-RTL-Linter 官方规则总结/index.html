Vivado RTL Linter 官方规则总结

Vivado RTL Linter 官方规则总结

本文档基于 AMD Xilinx 官方文档《Vivado Design Suite User Guide: Synthesis (UG901)》中的 RTL Linter 规则列表整理，并补充了实际开发中常见但官方表格略过的隐藏规则。Linter 是在代码编译和综合前检查潜在硬件电路问题的防线。

📑 官方参考链接: Vivado Synthesis User Guide - List of Linter Rules

1. ASSIGN 类规则 (赋值与信号相关)

这类规则主要关注算术运算、信号位宽、驱动与赋值类型等问题。

  • ASSIGN-1: 算术溢出 (Arithmetic overflow)

    • 官方说明：对于算术表达式，目标位宽不足以容纳结果的完整精度时触发。
    • 严重性：【警告-强烈建议修改】。会直接导致高位数据丢失，计算结果错误。
    • 消除方案：确保存储计算结果的寄存器/线网位宽足够大（例如两个 8-bit 相加，结果应为 9-bit）。

  • ASSIGN-2: 操作数符号混合 (Operands have mixed signs)

    • 官方说明：在算术运算中，当操作数具有不同的符号类型时触发。（注：在 Verilog 中，有符号数和无符号数混合运算时，统一被视为无符号数处理）。
    • 严重性：【警告-建议修改】。非常容易引发非预期的负数计算错误。
    • 消除方案：使用 $signed() 或 $unsigned() 显式转换操作数，统一符号类型后再运算。

  • ASSIGN-3: 移位器溢出 (Shifter overflow)

    • 官方说明：在移位操作中，如果移位值大于结果的尺寸，导致结果全为 0 时触发。
    • 严重性：【严重-必须修改】。通常代表逻辑设计有误，或者移位变量没有做范围限制。
    • 消除方案：检查移位位数是否合理，添加防止过度移位的保护逻辑。

  • ASSIGN-4: 数组/向量越界访问 (Out-of-bounds Array Access)

    • 补充说明：(注：UG901官方表格中跳过了此编号，但在 Vivado 实际 Linter 中存在) 当对向量（如 reg [7:0] a）或数组进行索引时，索引值超出了其定义的边界（如访问 a[8]）时触发。
    • 严重性：【严重-必须修改】。越界读取在仿真中通常返回 X 态，综合后可能全 0；越界写入会被直接忽略，导致数据丢失和严重逻辑错误。
    • 消除方案：检查代码中的索引变量（特别是 for 循环中的迭代器），确保其被严格限制在 [MSB:LSB] 范围内。

  • ASSIGN-5: 信号位未赋值 (Signal bits not set)

    • 官方说明：当信号的一个或多个 bit 没有被赋值时触发。
    • 严重性：【严重-必须修改】。未赋值的内部信号悬空可能产生不确定的硬件行为（综合后可能接地或引发多驱动错误）。
    • 消除方案：确保对向量信号的所有 bit 都进行了完整的赋值。

  • ASSIGN-6: 信号位未使用 (Signal bits are not used)

    • 官方说明：当信号的一个或多个 bit 没有被读取（没被其他逻辑使用）时触发。
    • 严重性：【提示-可改可不改】。多余的代码，综合工具会自动优化掉（Optimize away），但可能意味着你忘记连接某些逻辑。
    • 消除方案：确认是否漏写逻辑，如果是故意留空，可忽略或将其移除以保持代码整洁。

  • ASSIGN-7: 数组中存在多重赋值 (Multiple assignments in an array)

    • 官方说明：当数组中的一个或多个 bit 被多次赋值时触发。这会导致后续流程中出现多驱动（multi-driver）问题。
    • 严重性：【致命-必须修改】。硬件无法实现多个源同时驱动同一根线。
    • 消除方案：检查代码，确保数组的每个元素在同一时刻只能被一个逻辑或 always 块驱动。

  • ASSIGN-8: 不同尺寸的数组比较 (Comparison of arrays of different sizes)

    • 官方说明：当直接比较不同维度的数组类型的信号时触发。
    • 严重性：【警告-建议修改】。比较行为可能会因为位宽对齐问题导致预期之外的结果。
    • 消除方案：在比较前，使用显式的位拼接 {} 补齐位宽。

  • ASSIGN-9: IO 位未赋值 (IO bits are not set)

    • 官方说明：当 I/O 端口的一个或多个 output bit 没有被赋值时触发。
    • 严重性：【严重-必须修改】。导致输出端口悬空，下游模块将接收到 X 态或错误数据。
    • 消除方案：对所有 output 端口提供确定的驱动源（哪怕是赋 0）。

  • ASSIGN-10: IO 位未使用 (IO bits are not used)

    • 官方说明：当 I/O 端口的一个或多个 input bit 没有被读取时触发。
    • 严重性：【提示-可改可不改】。
    • 消除方案：如果该输入端口确实不需要，可以保留警告或从模块端口列表中删除。

  • ASSIGN-11: 阻塞与非阻塞赋值混用 (Mixed blocking and non-blocking assign)

    • 官方说明：标记对同一信号混合使用了阻塞（=）和非阻塞（<=）赋值。
    • 严重性：【严重-必须修改】。会导致仿真和综合不一致（Simulation-Synthesis Mismatch）。
    • 消除方案：时序逻辑只用 <=，组合逻辑只用 =。

  • ASSIGN-12: 模块例化的输入未连接 (Unconnected inputs on module instances)

    • 官方说明：对实例化的模块的悬空输入引脚发出警告。
    • 严重性：【严重-必须修改】。子模块缺少输入激励，功能一定不正常。
    • 消除方案：补全模块例化时的所有 input 端口连接。

2. INFER 类规则 (逻辑推断)

用于检查 Vivado 从 RTL 中推断出特定硬件结构（如 Latch 或 Loop）的情况。

  • INFER-1: 推断出锁存器 (Inferred latch)

    • 官方说明：推断出了锁存器（Latch）而不是寄存器（Register），这通常是无意的。
    • 严重性：【严重-必须修改】。Latch 在 FPGA 中会造成静态时序分析困难和毛刺。
    • 消除方案：在组合逻辑的 always 块中，补全所有的 if-else 和 case 的 default 分支，或在开头给出默认赋值。

  • INFER-2: 完整的 case 语句 (Full case statement)

    • 官方说明：报告 case 语句已经覆盖了所有情况，或者包含了一个 default 语句。
    • 严重性：【提示-无需修改】。这是一条良好代码风格的确认信息。

  • INFER-3: 检测到 case 等式检查 (Case equality detection)

    • 官方说明：使用了全等号 ===，Vivado 综合会自动将其转换为逻辑等号 ==。
    • 严重性：【警告-建议修改】。在可综合 RTL 中 === 是无效的（它用于仿真中判断 X 和 Z 态）。
    • 消除方案：在 RTL 代码中一律使用 == 代替 ===。

  • INFER-4: 检测到组合逻辑环路 (Combinational loop detection)

    • 官方说明：标记 RTL 信号中，1 个或多个 bit 通过组合逻辑环路被赋值。
    • 严重性：【致命-必须修改】。组合逻辑环路会引起无休止的震荡，无法在真实硬件上稳定工作。
    • 消除方案：打破死循环，例如在反馈路径中插入 D 触发器（改为时序逻辑）。

3. RESET 类规则 (复位信号相关)

  • RESET-1: 同一块中混合异步复位 (Mixed asynchronous reset in same block)

    • 官方说明：报告在同一个时序 always/process 块中存在多种类型的异步复位。
    • 严重性：【严重-必须修改】。FPGA 底层触发器通常只有单一的异步复位/置位端口，无法映射多种异步逻辑。
    • 消除方案：统一复位信号，如果需要多个条件复位，可以在外部使用逻辑门合并成一个单一的复位信号。

  • RESET-2: 缺少异步复位逻辑 (Missing asynchronous resets)

    • 官方说明：在 always/process 块的敏感列表中存在异步复位信号（如 posedge rst），但在块内部逻辑中没有指定相应的复位行为。
    • 严重性：【严重-必须修改】。语法和意图矛盾。
    • 消除方案：在 always 块内部加上 if (rst) begin ... end 逻辑。

  • RESET-3: 使能信号包含同步复位 (Enable contains synchronous reset)

    • 官方说明：在同一个块中，如果一个没有同步复位的寄存器，其使能信号是由同步复位驱动的，则发出警告。
    • 严重性：【警告-建议修改】。这会导致综合工具推断出复杂的控制集（Control Sets），消耗额外资源。
    • 消除方案：重构逻辑，将复位逻辑和普通的使能逻辑清晰地剥离开来。

4. CLOCK 与 QOR 类规则

  • CLOCK-1: 模块使用了双边沿时钟 (Module using both clock edges)

    • 官方说明：如果模块同时使用了时钟的上升沿和下降沿，进行报告。
    • 严重性：【警告-建议修改】。FPGA 一般不推荐在普通逻辑中混用双边沿，容易导致半个周期的时序极难满足（除非是特意的 DDR 接口设计）。
    • 消除方案：统一使用 posedge clk 触发。

  • QOR-1: 算术运算符不可合并 (Arithmetic operators are not mergeable)

    • 官方说明：当两个连续的算术操作符无法被合并优化时触发。
    • 严重性：【提示-建议关注】。QoR (Quality of Results) 关系到电路性能，无法合并意味着可能会消耗更多的 DSP 或产生较长的逻辑延迟。
    • 消除方案：检查是否可以通过调整代码结构（如添加括号改变优先级、提取公因式）来帮助综合工具合并表达式。

5. 附录：官方规则参考表格 (英文原版)

以下表格内容提取自 Vivado 官方综合指南 (UG901) 原文，供快速参考对齐：

Name ID name Description
Arithmetic overflow ASSIGN-1 For arithmetic expressions when the target is not large enough to hold the full precision of the result.
Operands have mixed signs ASSIGN-2 In an arithmetic operation, when operands have different signs.Note: In Verilog, mixed-sign operands are treated as unsigned.
Shifter overflow ASSIGN-3 In a shift operation, when the shift value is larger than the size of the result. The result is in all 0’s.
Signal bits not set ASSIGN-5 When one or more bits of signal are not set.
Signal bits are not used ASSIGN-6 When one ore more bits of a signal are not read from.
Multiple assignments in an array ASSIGN-7 When one or more bits in an array have been assigned multiple times. Could lead to multi-driver issues later in flow.
Comparison of arrays of different sizes ASSIGN-8 When signals of array types of different dimensions are directly compared.
IO bits are not set ASSIGN-9 When one or more bits of an I/O are not set.
IO bits are not used ASSIGN-10 When one or more bits of an I/O are not read.
Mixed blocking and non-blocking assign ASSIGN-11 Flag mixed usage of blocking and non-blocking assignment for same signals.
Unconnected inputs on module instances ASSIGN-12 Warn for unconnected pin for instantiated module instance.
Module using both clock edges CLOCK-1 Report module if both clock edges are used.
Inferred latch INFER-1 Latch is inferred instead of register, which can be unintended.
Full case statement INFER-2 Case statement covering all conditions or has a default statement
Case equality detection INFER-3 When case equality === is used, Vivado synthesis automatically converts it to logical equality ==.
Combinational loop detection INFER-4 Flag RTL signal within which 1 or multiple bits are assigned through combinational loop.
Arithmetic operators are not mergeable QOR-1 When two consecutive arithmetic operators cannot be merged.
Mixed asynchronous reset in same block RESET-1 Report sequential always/process block which has more than one types of asynchronous resets.
Missing asynchronous resets RESET-2 Report registers within always/process block when there is an asynchronous reset in sensitivity list but the reset logic not specified.
Enable contains synchronous reset RESET-3 Issue warning when register without synchronous reset has its enable driven by synchronous reset within same always/process block.
