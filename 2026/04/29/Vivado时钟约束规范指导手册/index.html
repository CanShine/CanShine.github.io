Vivado 时钟约束规范指导手册

Vivado 时钟约束规范指导手册

文档版本: V1.1 (增加典型应用场景与虚拟时钟详解)

适用对象: FPGA 逻辑工程师、数字前端设计工程师

适用工具: Xilinx Vivado Design Suite

1. 概述

在 FPGA 时序驱动的设计流程中，时钟约束是静态时序分析（STA）的基石。时序分析工具必须明确所有时钟的频率、占空比以及时钟之间的相位关系，才能准确计算建立时间（Setup time）和保持时间（Hold time）。

1.1 核心黄金法则

决定一个时钟是否需要手动约束，遵循以下基本原则：
- 必须手动约束：从 FPGA 外部物理引脚输入的主时钟，以及在 FPGA 内部通过普通逻辑（非专用时钟 IP）生成的时钟。
- 工具自动推导（无需手动约束）：通过 Vivado 官方专用 IP（如 Zynq PS、MMCM/PLL 等）生成或输出的时钟（前提是其源时钟已被正确约束）。

2. 详细场景分类与约束规范

2.1 必须手动添加约束的场景

2.1.1 外部输入主时钟 (External Input Primary Clock)

  • 场景描述：通过 FPGA 外部晶振或外部芯片输入到 FPGA 时钟引脚的时钟信号。
  • 典型应用场景：
    • 外部板载晶振：如 50MHz / 100MHz 有源晶振输入。
    • 摄像头接口 (DVP等)：摄像头传感器随路输出的像素时钟（PCLK）。FPGA 作为接收端，必须对输入的 PCLK 进行 create_clock 约束。
    • 以太网 PHY：PHY 芯片输出给 FPGA 的 RXCLK 或 TXCLK。
    • SPI 从设备 (Slave)：FPGA 作为 SPI Slave 时，外部主控发来的 SPI_SCK。
  • 工具行为：Vivado 无法预知外部硬件的频率，不会自动添加。
  • 约束规范：必须使用 create_clock 定义为主时钟。

2.1.2 时钟输出到外部 (Clock Forwarding)

  • 场景描述：将 FPGA 内部时钟通过物理引脚输出给外部芯片（随路时钟源同步输出）。
  • 典型应用场景：
    • 摄像头主时钟驱动：FPGA 输出 MCLK 给摄像头传感器作为系统参考时钟。
    • 高速 SPI 主设备 (Master)：FPGA 生成并向外输出 SPI_SCK，同时随路输出 MOSI 数据。
    • RMII/RGMII 接口：FPGA 向外部 PHY 芯片提供时钟。
  • 工具行为：Vivado 不会自动添加输出端口的时钟属性。
  • 设计规范：强烈建议使用 ODDR（Output Double Data Rate）原语转发时钟，严禁直接使用组合逻辑引出。
  • 约束规范：使用 create_generated_clock 定义衍生时钟。

2.1.3 逻辑分频/倍频时钟 (Logic Generated Clocks)

  • 场景描述：通过触发器级联、计数器翻转等普通 Fabric（FPGA 可编程逻辑阵列，即普通的查找表 LUT 和触发器 FF 资源）生成的时钟。
  • 典型应用场景：
    • 低速接口时钟生成：如低速 IIC (I2C) 的 SCL 线，或者极低速的 SPI_SCK，有时开发者为了图方便会用计数器翻转直接生成（注：更规范的做法是使用时钟使能 Clock Enable 而非生成物理时钟）。
  • 工具行为：Vivado 不会自动添加此类时钟约束。
  • 设计规范：强烈不建议在 FPGA 中使用该方式生成时钟（会导致严重的 Clock Skew，时钟偏斜极大）。如因特殊情况必须使用，务必手动约束。
  • 约束规范：使用 create_generated_clock。

2.1.4 虚拟时钟 (Virtual Clocks)

  • 场景描述：用于建立一个无物理节点的理想参考坐标系，通常用于约束系统同步接口的输入输出延迟（Input/Output Delay），此时外部芯片的时钟并未物理连接到本 FPGA 内部。
  • 典型应用场景：
    • 上游芯片时钟未接入：上游有一颗 ADC 芯片和 FPGA 共用板上的同一颗晶振（System Synchronous），ADC 发数据给 FPGA 但不发时钟。我们需要约束 FPGA 的数据输入时间，这就需要建一个代表“板载晶振到达ADC芯片端”的虚拟时钟。
    • 高速 SPI 输出约束：FPGA 作为 SPI Master 发送 SCK 和 MOSI 到外部 Flash。为了精准设置 set_output_delay，我们需要一个参考系来代表“Flash 芯片内部看到的 SCK”，这时可以创建一个虚拟时钟，并通过设置虚拟时钟与物理 SCK 之间的延迟（Latency/Uncertainty）来模拟 PCB 走线延迟。
  • 工具行为：需要人为创建一个理想坐标系，手动添加。
  • 约束规范：使用没有绑定任何物理端口（[get_ports ...]）的 create_clock。

2.2 Vivado 自动推导的场景（无需手动约束时钟本身）

2.2.1 PS 端输出时钟 (Zynq PS Clocks)

  • 场景描述：Zynq-7000 或 Zynq Ultrascale+ 的 Processing System (PS) 输出给 Programmable Logic (PL) 的时钟（如 FCLK_CLK0、pl_clk0）。
  • 架构提示：在 Zynq 系统中，PL 端一般优先使用 PS 时钟。由于 PS 端内部包含强大的 PLL 资源，为了节省外部晶振和 PCB 布线，可编程逻辑阵列（Fabric）的工作时钟通常由 PS 配置产生。
  • 工具行为：在 Block Design 中配置好频率并生成 Output Products 后，Vivado 会自动生成相应的 XDC 约束。
  • 开发建议：无需干预，直接使用。

2.2.2 专用时钟 IP 输出时钟 (MMCM / PLL / Clocking Wizard)

  • 场景描述：使用 FPGA 内部专用时钟管理单元（MMCM/PLL）生成的倍频、分频、相移时钟。
  • 工具行为：只要 MMCM/PLL 的输入侧源时钟已存在合法约束，Vivado 的时序分析引擎会穿过该 IP，根据 IP 配置参数自动推导出所有输出端口的时钟频率和相位。
  • 开发建议：只需确保最源头的输入主时钟有约束即可，严禁对 MMCM 的输出引脚重复使用 create_clock。

2.3 时钟关系与异常约束规范

2.3.1 时钟多路复用关系 (Clock Multiplexing / BUFGMUX)

  • 场景描述：两个独立时钟（如 clk_A 和 clk_B）进入 BUFGMUX，由控制信号选择其一输出。
